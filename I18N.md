# English version of p2pie.com — conventions

Same URLs for both languages. `middleware.ts` picks the language per visitor and rewrites English visitors to
generated copies in `pages/xen/*` (made by `scripts/gen-en-pages.js` before build; never edit or commit them).
Russian output must stay exactly as it is today; English is added next to it.

## Tools (services/i18n.tsx)
- Components: `const t = useT();` then `t("Русский текст", "English text")`. Keep the Russian argument byte-identical
  to the current string. `useLocale()` gives `"ru" | "en"`.
- Plain functions/helpers that produce text: add a parameter `locale: Locale = "ru"` (optional, default ru, so
  untouched callers keep working) and use `tr(locale, "…", "…")`. Pass `useLocale()` from the components that call them.
- `getStaticProps(ctx)`: `const locale = localeOf(ctx);` — the English page copies call it with `ctx.locale = "en"`.
  Use `tr(locale, …)` for SEO title/description/breadcrumbs built there, and pass `locale` to loaders that fetch
  localized CMS content. Do not change `revalidate`, paths or data otherwise.
- CMS entities with `ru_name`/`en_name` (payment methods, cities, top parameters, popular groups, selector sections…):
  `pickName(entity, locale)` or `pickName(entity, locale, "description" | "title" | "label" …)`.
  Never change places where `en_name` is used as a slug, key or for matching — only displayed text.
- Short CMS types now have `en_*` fields: x-faq (`en_question`, `en_response`), x-faq-category (`en_description`),
  p2p-level (`en_title`, `en_description`), p2p-ad (`en_title`, `en_description`, `en_details`), p2p-condition
  (`en_title`, `en_description`), exchanger-tag (`en_name`, `en_description`), country (`en_name`, `en_preposition`).
  Add them to the GraphQL queries and show them on English pages with fallback to Russian.
- Dates/numbers: `toLocaleString(intlLocale(locale), …)` instead of hardcoded `"ru-RU"`. Russian plural helpers get an
  English branch (`1 review` / `2 reviews`).
- `router.pathname` is `/xen/...` on English pages: use `usePublicPathname()` for comparisons (active menu etc.).
- Mass content is NOT translated: articles, direction/buy/sell/city SEO texts (dirs-text, mass-dirs-text, text-box
  long `text`). On English pages: long SEO text bodies of direction/buy/sell/map pages are hidden; H1/titles built
  from templates are translated; article pages keep the Russian body with English chrome and a short note
  "This article is available in Russian only."
- User content (reviews, replies, maker descriptions) stays as written.

## English style
Natural, short UI English. Glossary: обменник = exchanger, мониторинг обменников = exchanger monitoring,
направление = exchange direction (or "pair" in tight UI), курс = rate, резерв = reserve, отзыв = review,
мейкер = maker, сделка = deal, оффер/предложение = offer, наличные = cash, город = city, Главная = Home,
Курсы обмена = Exchange rates, Карта офисов = Office map, Блог = Blog, Для обменников = For exchangers.

## Rules for parallel work
- Edit only files in your assigned area, with the Edit tool (never rewrite a whole existing file with Write).
- You may add an optional trailing `locale` parameter to a helper outside your area only if unavoidable; prefer
  translating at your call site.
- Typecheck: `docker run --rm -v "$PWD":/app -w /app node:20-alpine node_modules/.bin/tsc --noEmit -p .`
  (run from /home/martin/Desktop/projects/p2pie/front-i18n). Other agents edit other files at the same time, so
  ignore errors in files outside your area unless you caused them.
- Do not commit; do not touch middleware.ts, scripts/, pages/xen, services/i18n*.
